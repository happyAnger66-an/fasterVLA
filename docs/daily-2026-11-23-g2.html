名词解释

读表时先看这一节。单位：跟踪/跳变为 mrad，速度为 rad/s，r2r 为 ms。

指标含义大小怎么读
合块Hz每秒合块（换计划）次数。由 prefix/buffer（如 4+4）节流；未节流时可达十多 Hz。适中：过密易抖；4+4 后大约几 Hz 较正常。不是越大越好。
臂跟踪p95 / 跟踪p95臂关节 |cmd−meas| 的 95 分位（贴命令的程度）。越小越好
>100mrad / >100跟踪误差超过 100mrad 的时间占比。越小越好（接近 0）
交接参考跳 / 参考跳 p95合块瞬间参考轨迹的空间跳变幅度。越小越好（接缝更顺）
命令速度 / 速度 p95命令关节速度的高分位，反映「跑得有多猛」。看加速：κ↑ 通常变大；若很大且跟踪差 → 跟不住。
empty / starved计划缓冲挖空次数 / 估延迟超过剩余步数的次数。都要 ≈0；有数说明推理或节流跟不上。
rem↓剩余模型帧的下限（计划还剩多少）。箭头提醒别掉太低。越大越安全；过低易 empty。
dur该次 run 时长（秒）。中性：长跑统计更可信。
r2r推理请求 → 结果就绪的墙钟延迟（request-to-ready）。越小越好；今日 ~29ms 说明推理不紧。
κ / tracker / p/b / filter时间轴倍速；跟踪器（none/lead/mpc）；prefix/buffer 合块门；臂路径滤波（如 ZP）。配置列，用于对照，无「大小好坏」。

一句话：跟踪 / 跳变 / empty·starved / r2r → 小好；rem → 别太小；合块Hz → 适中；速度 → 反映快不快，要和跟踪一起看。

1. 今日结论

  • 路径平滑有效：合块节流（4+4）+ ZP DCT@3Hz + pchip 后，κ=1 体感几乎不抖。
  • 均匀加速可用：uniform κ=1.2→1.7→1.9 速度可感；默认 kappa_max 已提到 2.0。
  • 推理不是瓶颈：高κ下 empty/starved 多为 0，剩余帧 >14，r2r≈29ms，推理占空比约 15–25%。
  • Lead 有利于贴轨：none 在高κ下体感跟随变差（植物滞后）；lead 补 τ 后更快更贴。
  • 8+8 在 κ≥1.9 易左右摆：臂跟踪/交接参考跳明显差于 4+4（以空间跳变与体感为准）。

3. 当前问题

  1. 合块交接跳变：高κ下 merge 处参考/命令空间跳变更大，8+8 尤甚 → 犹豫/左右蹭（以跟踪/参考跳与体感为准）。
  2. 高κ + 大 prefix：2.0·lead·8+8 臂跟踪 p95≈198mrad、交接命令跳≈32mrad；2.0·4+4 合块更密、跟踪更好，需结合体感。
  3. none 贴轨变差：无超前时实测落后参考；高速下更明显，不宜作为高κ默认 tracker。
  4. MPC 曾顶软限位：早期 κ=1.1·mpc 因 ±π 盒松于 GDK 限位 abort；已改为 GDK 限位 + 下发前 clip。
  5. 双进程干扰：今日多次「摆动」实为其它控制进程抢臂，分析前需确认单 controller。
  6. QP 时间轴：体感犹豫，且与「加速后合块现象」易混淆；加速主路径暂用 uniform。

4. 下一步优化计划

  1. 默认工作点固化：lead + κ=1.8~1.9 + prefix/buffer=4/4 + ZP@3Hz + pchip + uniform + hold-gripper；写入文档/示例命令。
  2. 合块策略：高κ不要盲目加大 prefix；优先 4+4。可选实现 prefix ≈ f(κ) 或墙钟目标合块间隔（例如 ≥120ms）。
  3. Lead 可调：暴露 --lead-gain / --max-lead，在贴轨与少摆之间折中。
  4. 交接平滑：移植老栈 velocity-matched handoff / 降低合块处 cmd 跳变（治 8+8 空间跳变）。
  5. 跨 chunk ZP：试 zero_phase_dct_cross 减轻交接锯齿。
  6. QP：补 prefix 时长锁定后再做 κ A/B；当前不作为加速默认。
  7. 工程：execute 启动检测/提示其它控制进程；日报指标脚本入库便于明日复用。
  8. 提交：本地未 commit 的 4+4/ZP/pchip/限位/kappa_max=2.0 等改动择机入库。
