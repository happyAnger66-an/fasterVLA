PlanBuffer：模型步是唯一尺子

控制环与推理环共享同一条计划。进度用小数模型步计量， 而不是假设「每帧固定 1/30 秒」。下面用一条时间轴动画说明 advance / prefix(d̂) / merge / 晚到丢弃。

1. 存什么

2. 谁调用什么（一把锁）

控制环 · 100 Hz

  • advance(dt_real, alpha) — 沿 step_dt 推 progress
  • reference(t_now, …) — 插值给 tracker 下发
  • 接触时 alpha=0，进度冻结

推理线程

  • prefix(d̂) — 开推前冻前缀给 RTC
  • merge(timed, anchor) — 结果到达后接入
  • 比当前计划旧的结果 → 丢弃

墙上时钟 vs 模型步

控制环每拍贡献真实时间 dt_real。要换算成模型步，必须在当前 step_dt[] 上累加——加速后各步时长可以不均匀，不能再用常数 1/policy_fps。

蓝点 = 控制拍 · 紫点 = 推理事件（示意）

3. 故事板：一次推理交接

0

起点

计划已就位，progress 在某个模型步上。控制环持续 advance。

1

advance

把墙钟 dt_real 换成模型步增量：在 step_dt 上「走完」当前步剩余时间，再进入下一步。

2

估 d̂ → prefix

用近期推理延迟 P95（+ margin）估墙钟 L̂，再沿 step_dt 从当前 progress 累加到覆盖 L̂ 的模型步数 → d̂（上取整）。 prefix(d̂) 取出这段前缀交给 RTC：告诉模型「你回来时机器人大概走到这」。

3

推理进行中

控制环不停：继续 advance。真实走过的步数可能 < 或 > d̂。

4

merge

结果到达时用实际 progress 算延迟 d，从新 chunk 的第 d 步接到当前计划。记录 d̂ − d 便于调参。

5

晚到丢弃

若结果对应的计划世代已经过期（比当前缓冲区更旧），整段 丢弃，绝不回写——避免过期动作覆盖已经更前面的计划。

progress' = advance(progress, dt_real · α) // α=0 冻结
d̂ = ⌈ wall_to_model_steps(progress, L̂, step_dt) ⌉
prefix = plan[progress … progress + d̂]
d = model_steps_elapsed(anchor → now) // 实际延迟
plan ← splice(new_chunk from index d) // 或 discard if stale

4. 为什么比「固定帧配额」好

老栈常用固定 prefix + buffer 帧（如 4+4）。加速后容易出现： 结果早到却要等交接点，或 buffer 掏空后空转等推理。

PlanBuffer 用 d̂ / 实际 d 动态对齐：早到就按实际进度接入， 晚到就丢掉，不再为「凑满配额」停顿。旋钮变成 T_infer_min、T_switch_min、latency_margin_ms。
