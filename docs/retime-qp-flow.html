TimeAxisQP 是什么 QP？

是的：标准盒约束二次规划（box-constrained QP）。 路径路点 waypoints 固定不进决策；只优化每段播放速率。 全部不等式最终都折成对 s 的上下界，所以用 active-set Newton （box_qp）即可精确求解；KKT 失败再退 L-BFGS-B / OSQP。

1. 决策变量

s = (s_0, s_1, …, s_{H−1}) ∈ ℝ^H s_i ≜ 1 / dt_i （第 i 段的「帧率」，单位 1/s） dt_i = 1 / s_i （到达 waypoints[i] 相对上一结点的墙钟时长）

不是决策关节角。几何路径已由策略给出； L2 只重新分配「每一段花多少时间」。

2. 已知量（参数，不优化）

dp ∈ ℝ^{H×14}臂差分：相邻结点关节位移（含 state→wp[0]）
κ, policy_fps意图倍速；参考速率 s_ref = fps·κ
dt_min, dt_max时长盒 → s ∈ [1/dt_max, 1/dt_min]
v_max ∈ ℝ^{14}每关节角速度上限（可含 soft-lead 导出）
λ_time, λ_acc目标权重（默认 0.1 / 1.0）
lock_durations可选：前缀帧钉死的墙钟时长
r2r budget可选：inference buffer 窗最小墙钟

3. 目标函数（凸二次）

与 realtime-vla-v2 / 老栈 arm_timeline 相同，两项：

J(s) = (λ_time / s_ref²) · Σ_i (s_i − target)² + (λ_acc / scale) · Σ_i ‖ s_{i+1} dp_{i+1} − s_i dp_i ‖₂² scale = mean( ‖dp_i‖² · s_ref² ) + ε # 使两项量级可比 target 初值 = s_ref，校准循环中可微调（见下）
  • 时间项：把各段速率拉向 target（≈ κ·fps），整体更快/更慢。
  • 加速度项：惩罚相邻段「速度向量」 s·dp 的跳变，避免时间轴抖、段间忽快忽慢。

写成标准 QP：

min_s ½ sᵀ H s + qᵀ s H = rate_hessian(dp, s_ref, λ_time, λ_acc) # 对称正定 q = −2 · wt · target · 1 # wt = λ_time / s_ref² # 注：代码里目标是 ½ s'Hs + q's，与展开的 Σ(s−target)² 差一个常数，不影响 argmin

H 的对角含时间项 2·wt，以及加速度项对 ‖dp‖² / 交叉 dp_i·dp_{i+1} 的贡献 （见 rate_hessian）。

4. 约束条件（全部变成盒子）

原始物理约束 → 对每个 s_i 的区间 [lower_i, upper_i]：

时长盒 dt_min ≤ dt_i ≤ dt_max
⇔ 1/dt_max ≤ s_i ≤ 1/dt_min
即 s_min ≤ s_i ≤ s_max
速度盒 对每关节 j：|dp_{ij}| / dt_i ≤ v_max_j
⇔ s_i ≤ v_max_j / |dp_{ij}|（|dp|≈0 则无约束）
取最紧关节：upper_i ← min(upper_i, min_j v_max_j/|dp_{ij}|)
buffer 窗
（可选）		 希望 Σ_{i∈[p,p+b)} dt_i ≥ budget
老栈用充分条件：窗内每帧 s_i ≤ b / budget
（平均速率上限；实现简单、仍是盒子）
prefix lock
（可选）		 RTC 引导段：dt_i = lock_i（给定）
⇔ lower_i = upper_i = 1/lock_i（等式钉死）
完整问题： min_s ½ sᵀ H s + qᵀ s s.t. lower_i ≤ s_i ≤ upper_i ∀ i = 0…H−1 # 无一般线性不等式 Ax≤b；全部是坐标轴对齐的盒子 # ⇒ box_qp / OSQP 都只处理 bound constraints

5. 求解与校准（在 QP 外包一层）

内层：固定 target 解一次 QP

_solve_rates

  1. 组 q = −2·wt·target·1
  2. box_qp(H,q,lower,upper)
  3. KKT 不过 → L-BFGS-B；或直接 OSQP

外层：校准 target

_calibrated_rates

加速度项会把 s 往小拽，实测倍速偏慢。 在未被 upper 封顶的 free 帧上估 achieved，令 target ← target · (s_ref/achieved)， 再解 QP，直到接近 s_ref（≤8 次）。

解出 s* 后：step_dt = 1/s*， lock 帧再强制盖回 lock_durations，打包成 TimedChunk。失败则整段退 UniformRetimer（常数 dt=1/(κ·fps)）。

一句话：决策变量是每段速率 s=1/dt； 目标是「靠近 κ·fps + 段间速度平滑」的凸二次型； 约束是时长盒、关节 v_max、可选 buffer/lock——全部变成 lower ≤ s ≤ upper。所以叫 TimeAxisQP：动的是时间轴，不是轨迹形状。

原理动画：dp → 限速 → 非均匀 dt

示意一条 1 维「关节角」路径（6 个结点）。棕点位置永不移动； 段长 |dp| 决定「这段有多陡」。Uniform 匀速扫过； QP 在大 |dp| 段放慢、小段加快，总墙钟更接近 κ 意图且不超 v_max。

棕点 = 路点（路径固定） 粗段 = |dp| 大（陡） 蓝条 = Uniform 每段 dt 绿条 = QP 每段 dt 黄点 = 播放头

分步拆解

①–② 构造臂差分 dp

只取双臂 14 维 [8:22]（腰/头/夹爪不进 L2）。 把「当前臂状态」垫在路点前面，再 np.diff：

points = vstack([state_arm, actions[:, 8:22]]) # (H+1, 14) dp = diff(points, axis=0) # (H, 14) # dp[i] = 到达第 i 帧时，相对上一结点的关节位移

因此 |dp[5,j]| / step_dt[5] 就是第 5 段上关节 j 的平均速率—— 与单测「大位移帧被 v_max 限速」的契约一致。

③ 初始速率盒 + 参考速率

s_ref = policy_fps · κ # 想要的平均帧率，如 30×1.2 = 36 Hz s_min = 1 / dt_max_s # 最慢（默认 dt_max=80ms → 12.5 Hz） s_max = 1 / dt_min_s # 最快（默认 dt_min=15ms → ~66.7 Hz） lower[:] = s_min upper[:] = s_max

配置阶段已保证 1/(fps·κ) ∈ [dt_min, dt_max]，否则构造 TimeAxisQPConfig 直接抛错——避免 QP 无可行参考点。

④ 用 v_max 收紧 upper

_velocity_limit() 得到 14 维上限（显式 v_max_rad_s 与可选 soft-lead 导出上限 max_lead/(gain·τ) 取更紧者）。

per_joint[i,j] = v_max[j] / |dp[i,j]| # 该段该关节允许的最大 s velocity_cap[i] = min_j per_joint[i,j] # 该段最紧关节 upper[i] = min(upper[i], max(velocity_cap[i], s_min))

大位移段 |dp| 大 → velocity_cap 小 → 强制更长 dt。小位移段几乎不受限，可被 κ 拉快。 这就是「κ 给意图、QP 在物理盒内抹平」的核心。

⑤ 可选：inference buffer 墙钟地板

仅当 buffer_window_enabled=True（CLI： --qp-buffer-window）。用近期 r2r 的 p95 + margin 作预算：

budget = (p95(r2r_ms) + margin_ms) / 1000 # 秒 # 希望 Σ dt[prefix : prefix+buffer] ≥ budget # 等价：该窗内平均 s ≤ buffer / budget budget_cap = max(buffer / budget, s_min) upper[prefix : prefix+buffer] = min(upper[…], budget_cap)

F3 默认关闭：L1 的 d̂ 已承担「推理窗够不够」； 保留此开关是为了与老栈 A/B 对齐。

⑥–⑦ prefix lock 与校准窗

lock 钉死前缀

RTC / handoff 对齐旧计划

对前 locked 帧设 lower = upper = 1/lock_dt， 求解后仍再盖一遍 durations[:locked]， 数值上双保险。

free 校准哪些帧

决定 executed_speed 看哪一段

buffer 开：只在 [locked, prefix+buffer) 上校准（老栈行为）。 buffer 关：整段 [locked, H)——κ 提速单测依赖此路径。

⑧–⑨ 建 Hessian、求解、还原时长

rate_hessian(dp, s_ref, λ_time, λ_acc) 给出二次型 H 与时间项权重 wt，然后进入 校准循环。成功后：

durations = 1 / rates if locked: durations[:locked] = lock_durations # 强制覆盖 times = [0] + cumsum(durations) assert all(diff(times) > 0) # 否则抛错 → fallback

⑩ meta 与返回

retime_status active_set / lbfgsb / osqp（失败路径在外层写成 uniform_fallback）
executed_speed 校准窗上 (n_frames / fps) / wall_span，应接近 κ
time_target_speed 校准后的内部 target / fps（可能略高于 κ 以抵消加速项收缩）
velocity_limited_frames velocity_cap[i] < s_ref 的帧下标（大位移被限速）
locked_frames 前缀钉死帧数

model_dt 取 mean(durations) 仅作摘要； PlanBuffer 真正推进用的是整条 step_dt。

目标函数（与老栈一致）

变量 s ∈ ℝH，位移序列 dpi ∈ ℝ14：

min_s (λ_time / s_ref²) · Σ_i (s_i − target)² + (λ_acc / scale) · Σ_i |s_{i+1} dp_{i+1} − s_i dp_i|² s.t. s_min ≤ s_i ≤ s_max |dp_{ij}| · s_i ≤ v_max_j （已折入 upper） s_i = 1/lock_dt_i （locked 帧，lower=upper） （可选）buffer 窗平均 s ≤ buffer/budget

第一项把速率拉向 target（初值 = s_ref）； 第二项惩罚相邻段「速度向量」跳变，抑制时间轴抖动。 权重按 s_ref 归一，与 realtime-vla-v2 / arm_timeline.py 相同。

校准循环 _calibrated_rates

加速度正则会把所有 s 往 0 拽，导致实测倍速偏慢。 因此在 未被硬帽压住 的 free 帧上估实测帧率，回标 target（最多 calibrate_iters 次，默认 8）：

calibrate = { i ∈ free | upper[i] ≥ s_ref } # 排除已被 v_max/buffer 封顶的帧 loop: rates, solver = _solve_rates(H, wt, target, lower, upper) achieved = |calibrate| / Σ_{i∈calibrate} (1/rates[i]) ratio = s_ref / achieved if |ratio − 1| < 0.002: break target ← clip(target · ratio, 0.5·s_ref, 4·s_ref)

求解器选择（_solve_rates）

  1. solver=osqp → 直接 OSQP
  2. 否则先 box_qp（active-set Newton）；KKT 通过则标 active_set
  3. KKT 失败 → SciPy L-BFGS-B 兜底

外层 fallback

_retime_qp 本身不吞异常； TimeAxisQP.retime 用 try/except 包住： 任意失败（含「非正时长」）退回同 κ 的 UniformRetimer， 并写 meta.retime_status = "uniform_fallback" + retime_error。热路径上 PlanBuffer 始终能拿到合法 step_dt。

和 Uniform 的分工

Uniform

dt = 1/(κ·fps) 常数；无 v_max、无 lock。F2 默认，可靠基线。

TimeAxisQP

路径不变、时长按物理盒重分配；大位移段自动放慢。F3： run --retimer qp。
