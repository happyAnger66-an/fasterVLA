RTC 冻前缀 ≠ 不用重标 progress

你说得对：RTC 会把「推理期间预计要走的那段」冻住，交给新推理，让新 chunk 的关节值接得上。 但冻的是一段动作内容的副本，合块时仍会整段换成新数组——新数组从 0 起重新编号。 「回拨」改的是下标尺子，不是把机器人拉回已走轨迹。

一句话：RTC 回答「新 chunk 开头几帧的 q 该长什么样」； progress ← d_actual 回答「我已经在这开头里走到第几格了」。两件事叠在一起，缺一不可。

RTC 管什么

开推时拷贝 old[anchor : anchor+d̂]（+ leftover）送给模型 INPAINT。回来的新 chunk头部关节值 ≈ 这段冻结内容。关 RTC 也会 merge 重标，只是头部可能对不齐、更抖。

merge 管什么

waypoints ← new_chunk 整表替换。新表的 0 = 旧 anchor。飞行中已执行的是冻结段里的前 d_actual 帧，所以进度必须标成 d_actual，不是旧的 10。
