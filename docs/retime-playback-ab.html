fasterVLA · L2 播放对齐

A 均匀网格 vs B 非均匀 progress

同一条几何路径、同一套非均匀 Δt_i（重定时结果）之后， 怎么对齐到更高频的控制拍？下面左右对照播放。

棕点 = 模型步（路点，队列不重建） A：蓝点 = 控制拍队列（已重采样） B：绿点 = 控制拍下发值（常在两棕点之间） 墙钟「现在」
待命

方式 A 重采样到均匀网格

V2 re_allocate：时间轴上等间隔（控制拍），再 1 拍取 1 个队头

方式 B 非均匀 Δt + 小数 progress

队列仍是棕点；绿点才是每拍真正下发的值（lerp，多数不落在棕点上）

这一拍各自在干什么

A：队列已是控制网格上的离散点；本拍下发 future[0]，整步 pop。
B：本拍推进小数 progress；下发 = 相邻两棕点的线性插值（通常不是模型步）。

B 的插值到底是什么

控制环每拍固定 dt_ctrl（如 10 ms）调用：

advance(dt_ctrl) → progress 变成小数（如 2.37）
reference() → i0=⌊p⌋, frac=p−i0 → (1−frac)·w[i0] + frac·w[i0+1]

所以下发给 tracker 的往往不是黄/棕模型步， 而是两模型步之间的关节空间线性混合点。 只有 progress 恰好落在整数上时，下发值才等于某个模型步。

图中 B：路径上的绿点 = 各控制拍的下发值； 棕点只是插值两端的「标尺」，队列不重建。

为什么感觉和 A 没区别？

因为静态计划下，每拍下发的关节值本来就一样。 同一条几何路径 + 同一套墙钟采样时刻 + 同一种线性插值 → A 预先算进蓝点队列的值，和 B 每拍现场 lerp 出来的绿点，是同一个数。 图里左右游标重合，不是画错了。

真正不同的是尺子存在哪、合并怎么做：

  • A：播放队列改成控制网格；「第几个模型步」被冲掉 → RTC / merge 的 \(d̂\)、prefix 不好对齐。
  • B：队列仍是 H 个棕点 + step_dt；progress 是小数模型步 → prefix(d̂) / merge 天然按模型步接。
  • QP 只改 step_dt 时：B 改数组即可；A 要整段蓝点队列重算。

一句话：开环跟轨迹时 A≈B；异步换段 / RTC 时才必须用 B 的模型步尺子。
